# Функциональные требования

## Обозначения

- `Must` — обязательно для MVP и демонстрации.
- `Should` — желательно для расширенного сценария и устойчивости.

## Покрываемые сервисы

- `Morent core` (backend + frontend)
- `car-aggregator-project`
- `user-system-develop`
- `payment-service`
- `EmailService`
- `generator-service`

## Список требований

| ID | Сервис | Приоритет | Требование |
| --- | --- | --- | --- |
| `FR-01` | Morent core | Must | Платформа должна поддерживать регистрацию, вход и сессию пользователя. |
| `FR-02` | Morent core | Must | Платформа должна разделять доступ по ролям `user` и `admin`. |
| `FR-03` | Morent core | Must | Платформа должна отдавать каталог авто с фильтрами и страницей деталей. |
| `FR-04` | Morent core | Must | Платформа должна создавать аренду и запрещать пересечение броней одного авто. |
| `FR-05` | Morent core | Must | Платформа должна поддерживать избранное, комментарии и проверку "комментарий только после аренды". |
| `FR-06` | Morent core | Must | Админ-панель должна поддерживать CRUD по доменным сущностям и аудит действий. |
| `FR-07` | Morent core | Must | Сервис должен поддерживать загрузку медиа в объектное хранилище и выдачу URL. |
| `FR-08` | car-aggregator | Must | Агрегатор должен выполнять поиск авто по запросу с валидацией через DaData и данными CarAPI. |
| `FR-09` | car-aggregator | Must | Агрегатор должен исключать из результатов машины, уже "забранные" в `offers`. |
| `FR-10` | car-aggregator | Must | Агрегатор должен поддерживать регистрацию взятия/освобождения оффера (`purchase/release`). |
| `FR-11` | car-aggregator | Should | Агрегатор должен поддерживать fallback-стратегии поиска (exact/fuzzy/dadata). |
| `FR-12` | user-system | Must | Сервис пользователей должен поддерживать JWT-аутентификацию и управление пользователями (CRUD). |
| `FR-13` | user-system | Must | Сервис пользователей должен поддерживать RBAC: роли, права, назначения прав ролям. |
| `FR-14` | user-system | Must | Сервис пользователей должен поддерживать управление компаниями и привязку пользователей. |
| `FR-15` | user-system | Should | Сервис пользователей должен публиковать асинхронные события через RabbitMQ. |
| `FR-16` | payment-service | Must | Платежный сервис должен поддерживать создание счетов, пополнение, списание и переводы. |
| `FR-17` | payment-service | Must | Платежный сервис должен обеспечивать идемпотентность переводов по ключу операции. |
| `FR-18` | payment-service | Must | Платежный сервис должен поддерживать лимиты, историю операций и реверс перевода. |
| `FR-19` | payment-service | Should | Платежный сервис должен поддерживать batch-переводы и статистику по переводам. |
| `FR-20` | EmailService | Must | Email API должен принимать запрос на отправку, валидировать данные и ставить письмо в очередь. |
| `FR-21` | EmailService | Must | Worker должен асинхронно обрабатывать очередь, рендерить шаблон и отправлять письмо через провайдера. |
| `FR-22` | EmailService | Must | Сервис должен хранить и отдавать статус доставки письма по `correlationId`. |
| `FR-23` | EmailService | Should | Сервис должен принимать webhook статусы от провайдера с HMAC-проверкой подписи. |
| `FR-24` | generator-service | Must | Сервис генерации должен выдавать пароль и пароль по маске через HTTP API. |
| `FR-25` | generator-service | Must | Сервис генерации должен выдавать QR-код PNG по входной строке и размеру. |
| `FR-26` | generator-service | Should | Сервис генерации должен валидировать параметры маски и размера с понятными ошибками. |
| `FR-27` | Интеграция | Must | Morent должен интегрироваться с агрегатором для поиска/импорта авто в админке. |
| `FR-28` | Интеграция | Must | Morent должен использовать payment-service для создания и проверки статуса платежа аренды. |
| `FR-29` | Интеграция | Must | Morent должен инициировать email-уведомления через EmailService по ключевым событиям аренды. |
| `FR-30` | Интеграция | Should | Morent синхронизирует пользователей в user-system через Kafka (`morent.users`). |
