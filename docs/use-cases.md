## UC-01 Регистрация и вход пользователя

- Цель: получить доступ к личному кабинету и операциям аренды.
- Предусловия: пользователь не авторизован.
- Основной сценарий:
1. Пользователь отправляет форму регистрации.
2. Система создает пользователя.
3. Пользователь выполняет вход.
4. Система выдает токен/сессию.
- Негативные альтернативы:
1. Email уже существует — регистрация отклоняется.
2. Неверный пароль — вход отклоняется.

## UC-02 Поиск и бронирование автомобиля

- Цель: создать аренду на выбранный период.
- Предусловия: пользователь авторизован.
- Основной сценарий:
1. Пользователь фильтрует каталог и выбирает авто.
2. Вводит даты аренды.
3. Система проверяет пересечения бронирований.
4. Система создает аренду.
- Негативные альтернативы:
1. Даты некорректны (`end <= start`) — запрос отклоняется.
2. Есть пересечение с существующей бронью — запрос отклоняется.

## UC-03 Добавление автомобиля в избранное

- Цель: сохранить интересующие авто для быстрого доступа.
- Предусловия: пользователь авторизован.
- Основной сценарий:
1. Пользователь нажимает "добавить в избранное" в карточке авто.
2. Система создает связь `user-car`.
3. Пользователь видит авто в списке избранного.
- Негативные альтернативы:
1. Авто не существует — операция отклоняется.
2. Повторное добавление не создает дубль.

## UC-04 Импорт автомобиля из агрегатора

- Цель: пополнить каталог Morent через внешний агрегатор.
- Предусловия: администратор авторизован.
- Основной сценарий:
1. Администратор отправляет поисковый запрос в агрегатор.
2. Получает список подходящих авто.
3. Выбирает авто и инициирует импорт.
4. Авто появляется в каталоге Morent.
- Негативные альтернативы:
1. Агрегатор недоступен — отображается контролируемая ошибка.
2. Некорректные данные ответа агрегатора — импорт отклоняется.

## UC-05 Оплата аренды

- Цель: подтвердить аренду через платежный сервис.
- Предусловия: аренда создана.
- Основной сценарий:
1. Morent создает запрос в payment service.
2. Payment service обрабатывает платеж.
3. Morent получает итоговый статус оплаты.
4. Пользователь видит подтверждение оплаты.
- Негативные альтернативы:
1. Платеж отклонен — аренда остается в состоянии ожидания/ошибки.
2. Payment service недоступен — операция переводится в retry/pending.

## UC-06 Оставить комментарий после аренды

- Цель: оставить отзыв только при реальном опыте аренды.
- Предусловия: пользователь авторизован.
- Основной сценарий:
1. Пользователь отправляет комментарий и рейтинг.
2. Система проверяет факт аренды этого авто.
3. Комментарий сохраняется и отображается в карточке авто.
- Негативные альтернативы:
1. Аренды не было — возвращается `403 Forbidden`.

## UC-07 Просмотр и модерация данных в админке

- Цель: операционное управление платформой.
- Предусловия: пользователь с ролью `admin`.
- Основной сценарий:
1. Администратор открывает админ-панель.
2. Выполняет CRUD-операции по авто/пользователям/комментариям.
3. Система сохраняет изменения и записывает аудит-лог.
- Негативные альтернативы:
1. Не-админ пытается выполнить операцию — доступ запрещен.

## UC-08 Управление ролями и правами

- Цель: централизованно управлять доступом пользователей.
- Предусловия: администратор user-system авторизован.
- Основной сценарий:
1. Администратор создает/обновляет роль.
2. Назначает роли набор прав.
3. Привязывает роль к пользователю.
4. Изменения вступают в силу для защищенных endpoint.
- Негативные альтернативы:
1. Попытка удалить системную роль отклоняется.
2. Некорректный набор permission возвращает ошибку валидации.
